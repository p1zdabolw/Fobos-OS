# Fobos OS — дорожная карта этапов

Принцип: каждый этап — вертикальный срез, который «можно запустить и проверить».
Этап не закрывается без: сборки без предупреждений (`-Wall -Wextra -Werror`),
прогонов self-тестов (QEMU + host) и обновления этого документа.

## Легенда статусов

- [x] закрыт — [~] в работе — [ ] бэклог

---

## [x] FND-1. Сквозной путь загрузки и базовые сервисы

**Состав:**
- Система сборки: Makefile, x86_64 freestanding C11 (ядро, `-mcmodel=kernel`,
  `-mgeneral-regs-only`), PE32+ для UEFI через GNU ld `-m i386pep` + пост-патч
  Subsystem, NASM (`elf64` / `win64`).
- UEFI-загрузчик без внешних библиотек: собственные EFI-таблицы со
  static-assert'ами смещений, GOP, SimpleFileSystem, ExitBootServices с ретраем,
  начальные таблицы страниц (identity 4 ГиБ + higher-half 1 ГиБ).
- Контракт загрузчик↔ядро FBPI v0 (`docs/boot-protocol.md`) с checksum.
- Ядро: GDT (ring0/ring3), IDT, 32 обработчика исключений с полным дампом
  кадра и декодированием #PF, logging-подсистема с уровнями и кольцевым
  буфером, собственный kvsnprintf, физический аллокатор (bitmap, carved),
  драйвер 16550 UART, драйвер framebuffer (RGBX/BGRX/BitMask).
- Самопроверки: тесты в ядре (QEMU) + unit-тесты на host-инструментарии
  (один общий набор в `kernel/selftest/`).
- Отладочная инфраструктура: дамп карты памяти в ConOut, `isa-debug-exit`
  выход с кодом, трассировка исключений QEMU (`-d int`).

**Критерий готовности (выполнен):** `make verify` зелёный — загрузка под OVMF,
selftest 30/30, host 28/28, управляемый выход в QEMU, ноль предупреждений.

## [x] FND-2a. Интерактивность: ввод, время, экранный интерфейс (вставка между FND-1 и FND-2)

**Зависимости:** FND-1.
**Обоснование вставки:** этап даёт пользовательскую ценность («машина
отвечает на ввод») и является предпосылкой всего GUI-трека и планировщика
(таймер-квант). Полноценный FND-2 (buddy/VMM/ACPI/APIC/SMP) идёт следом
без изменений состава.
**Состав:**
- PIC 8259 (remap 0x20..0x2F, spurious-фильтр IRQ7/15) + диспетчер IRQ.
- PIT канал 0 @ 1000 Гц: тики, uptime, sleep_ms (hlt/стей busy-wait).
- 8042: полная инициализация (self-test, interface-тесты, dual-channel
  детекция пробой конфига, включение сканирования 0xF4, ACK-протокол).
- PS/2 клавиатура: сканкод-набор 1, US-раскладка, Shift/Ctrl/Alt/CapsLock
  (+LED через 0xED с pending-протоколом ISR), автоповтор программный,
  кольцевая очередь событий.
- PS/2 мышь: streaming, парсер пакетов (знаковое расширение, overflow,
  рассинхрон), кнопки, очередь.
- fbcon: текстовая консоль 8x8 (font8x8, public domain) поверх framebuffer:
  прокрутка, цвета, курсор-инверсия, вывод через klog-синк (паника видна).
- Экранная оболочка FND-2a: градиентный фон, панель с заголовком,
  статус-бар (память/uptime/координаты мыши), курсор-стрелка 12x18
  с сохранением фона.
- kshell — ядерная оболочка (диагностический интерфейс, уйдёт в user-space
  на FND-3): 14 команд, все реальные (help/about/uptime/ticks/mem/kbd/mouse/
  fbtest/font/condump/selftest/echo/crash/reboot).
- CI e2e: `scripts/qemu_selftest.py` сам «печатает» в гостя через HMP monitor
  (sendkey) и двигает мышь (mouse_move/mouse_button), проверяет смещение
  курсора и кнопки, повторный kselftest, fbtest и reboot (8042 reset).
**Известные ограничения:** UI в ядре (без процессов это честный прототип);
ASCII-шрифт (кириллица — точками) до Unicode-шрифта в GUI-этапах;
numpad — как цифры (numlock-режим).
**Критерий готовности (выполнен):** `make verify` зелёный — host 30/30,
QEMU: selftest 36/36, курсор смещается ровно на заданный вектор (+100,+60),
кнопки фиксируются, fbtest завершается клавишей, reboot гасит QEMU (exit 0);
ноль предупреждений `-Wall -Wextra -Werror`.

## [x] FND-2b. Системный старт: OOBE, пользователи, экран входа, boot-консоль

**Зависимости:** FND-2a.
**Обоснование вставки:** пользовательская ценность «ОС ведёт себя как ОС»
(первый запуск как в Windows 11, многопользовательский вход, сервисный
режим по Shift) до тяжёлого FND-2; предпосылка GUI-трека (готовые экраны
и примитивы) и FND-2c (появляется источник конфигурации).
**Состав:**
- FBPI v0.1: + `cfg_phys`/`cfg_size` (блоб настроек foboscfg), `boot_flags`
  (FBPI_BOOTF_CONSOLE), размер 176 -> 192 байта, смещения зафиксированы
  static_assert'ами, документация в docs/boot-protocol.md.
- common/: SHA-256 (FIPS 180-4, NIST KAT-тесты), foboscfg (сериализация
  настроек с SHA-256-тегом, KDF пароля 4096 итераций, валидация
  имён/hostname), общий шрифт font8x8 (ядро + загрузчик),
  fbpi_pixel_rgb (единый конвертер цвета ядра/загрузчика).
- Загрузчик: serial-лог (16550, маркеры CI), графика поверх GOP (lgfx),
  ConIn-ввод (lin: посимвольное редактирование, опрос Shift через EX и
  прямой порт 8042), boot manager (окно 1 c: ESC = сброс Setup,
  SHIFT = консоль ядра), графический OOBE-мастер (welcome/hostname/
  username/password/confirm/more/save), сохранение настроек в
  UEFI-переменную FobosSetup (NV, переживает перезагрузку и выключение).
- Ядро: splash (логотип, окно 3 c на Shift -> kernel console), экран входа
  (поля, кнопки, мышь, часы RTC), экран "setup required", сессии
  (login/logout/useradd/passwd, admin-права), RAM-база пользователей с
  KDF-проверкой, драйвер RTC (CMOS, BCD, реальные дата/время),
  sys/power (reboot через 8042, poweroff через PM1a_CNT q35), uidraw
  (примитивы: текст/поля/кнопки/курсор/фон), Ctrl+Alt+Del -> reboot.
- kshell: + whoami/date/hostname/users/useradd/passwd/logout/clear/
  poweroff; приглашение `user@host:~$` в сессии, `fobos(kconsole)>` в
  консоли ядра; статус-бар: сессия + часы RTC.
- Тесты: kselftest 40 (sha256/foboscfg+users/rtc/session), host 34;
  CI e2e — 4 сценария (qemu_selftest.py): OOBE-прогон с интерактивом и
  logout, персистентность переменной + неверный/верный пароль +
  Ctrl+Alt+Del, ESC-сброс -> новый OOBE, Shift -> kernel console ->
  whoami=maintenance -> poweroff.
**Известные ограничения:** рантайм-изменения (passwd/useradd/hostname)
неперсистентны до перезагрузки — персистентность появится с диском (FND-2c);
poweroff адрес зашит под q35 (ACPI FADT — FND-2); ASCII-шрифт;
OOBE в загрузчике — только клавиатура.
**Критерий готовности (выполнен):** `make verify` зелёный — host 34/34,
QEMU: selftest 40/40, все 4 сценария PASS (OOBE+логин+desktop+logout,
кросс-процессная персистентность настройки, ESC-сброс, Shift-консоль +
whoami + poweroff); ноль предупреждений.

## [x] FND-2c. Дисковая подсистема, GUI-десктоп, fos-режимы, амнезия (вставка перед FND-2)

**Зависимости:** FND-2b. **Статус: ЗАКРЫТ** (версия 0.3.0-fnd2c).

**Сделано:**
- PCI-энумерация (0xCF8/CFC, класс/вендор/BAR), драйвер AHCI: HBA init,
  COMRESET, IDENTIFY, READ/WRITE DMA EXT (LBA48, PRDT 1 запись ≤ 4 КиБ),
  тайм-ауты, разбор ошибок (TFES); блочный слой blk (AHCI → MBR → партиция
  0x0B/0x0C), оверлей амнезии ovl (RMW-блоки 4 КиБ, индекс с хеш-корзинами,
  лимит 4096 блоков = 16 МиБ, кадры из phys-пула).
- FAT32: mount (BPB/FSInfo), каталоги с LFN-чтением, файлы —
  чтение/запись/перезапись/удаление, кэш FAT write-through на обе копии,
  аллокация/освобождение цепочек, защита от циклов; чистая логика (fatp)
  общая с host-тестами. Storage-самотест ядра: write/read-verify/overwrite/
  delete на реальном диске при каждой загрузке.
- GUI-десктоп (gfx/desktop): два режима DSK_TUI/DSK_GUI; GUI — иконки,
  панель задач (кнопки окон, AMNESIA-индикатор, часы RTC), окна
  cmd/explorer/about/viewer с фокусом, перетаскиванием, закрытием;
  консоль kshell якорится в окне cmd (con_reanchor переживает перенос).
- kshell: `fos == gui|tui [--lock]` (+status), `amnezia on|off|status`,
  `storage`, `ls`, `cat`; — 28 команд.
- Персистентность: `\fobos\fobos.cfg` (режим десктопа — читают и загрузчик
  (FBPI_BOOTF_GUI), и ядро), `\fobos\setup.cfg` (первичный носитель
  аккаунтов; UEFI-переменная — фолбэк), метка тома FOBOSDISK,
  `\fobos\NOTES.TXT` — тестовые данные.
- CI: сценарий desktop (ESC-сброс → OOBE → storage/ls/cat → амнезия →
  fos-переключения → --lock → reboot → залоченный gui → возврат tui --lock);
  mkimg +NOTES.TXT+метка; selftest пересобирает ESP с нуля.

**Критерий (выполнен):** host 54/54; QEMU 5/5 сценариев; файл пишется,
читается, перезаписывается и удаляется на реальном диске при каждой
загрузке; `fos == gui --lock` переживает перезагрузку (загрузчик ставит
FBPI_BOOTF_GUI, ядро стартует в GUI).

**Осталось на следующие этапы (осознанно отложено):** GPT, fsck при
загрузке, LFN-запись (создание длинных имён), mkdir/rmdir в shell,
NTFS/ext-читалки; персистентность базы пользователей в файл (FND-4).

## [x] FND-2d. Полировка GUI: двойная буферизация, z-order, файловые команды (вставка перед FND-2)

**Зависимости:** FND-2c. **Статус: ЗАКРЫТ** (версия 0.4.0-fnd2d).
Мотивация: баг-репорт пользователя по FND-2c — (1) OOBE-текст выходит
за рамку бокса, (2) мерцание экрана в GUI, (3) окна наслаиваются
(контент терминала поверх верхнего окна; «explorer не видно, но название
видно»).

**Сделано:**
- Двойная буферизация fb: `phys_alloc_contig()` (смежные кадры), задний
  буфер геометрически идентичен VRAM (тот же pitch), все примитивы пишут
  в активную поверхность + dirty-флаг, `fb_present()` — один row-copy в
  VRAM. Мерцание (промежуточные состояния градиента/окон/курсора)
  устранено по построению; при нехватке памяти — честный откат на прямой
  режим с WARN. Буфер выделяется ПОСЛЕ kselftest (тест исчерпания видит
  полный пул).
- Композитор: консоль терминала рисуется НА z-позиции окна cmd (внутри
  цикла окон dsk_redraw) — верхнее окно перекрывает и рамку, и контент
  терминала; клиентская область cmd заливается `con_bg_rgb()` (швы сетки
  ячеек не показывают подложку). Клик — строго по z-порядку: окно под
  курсором (закрытие/драг/клиент), затем панель задач, затем иконки
  (раньше можно было закрыть перекрытое окно и «проскочить» клик сквозь
  верхнее окно к иконке).
- Коалесинг кадров: события мыши ставят `dsk_request_redraw()`, главный
  цикл собирает ОДИН кадр на пачку (`dsk_redraw_pending()`); условие
  «dirty-консоль → кадр» учитывает `dsk_cmd_open()` (нет холостых
  перерисовок при закрытом окне терминала).
- klog-синк: `klog_set_sink_level()` — в терминал только WARN+ (PANIC —
  всегда); INFO-поток подсистем больше не засоряет экран, serial — без
  изменений.
- OOBE: `oobe_wrap2()` — перенос длинных подзаголовков по словам
  (61-символьная строка «Settings will be written to platform storage
  (UEFI variable).» больше не выходит за бокс 480 px).
- kshell: `write` (создать/перезаписать текст), `rm`, `cp` (до 64 КиБ,
  K_ERANGE = честный отказ «больше лимита»), `sleep` (1..60000 мс,
  потолок от подвешивания) — 32 команды. Единая защита системных имён
  `fat_name_protected()` в fs/fat32 (один список для explorer, rm/write/cp;
  раньше копипастилась в desktop.c).
- Тесты: host 55 (+phys/contig), kselftest 61 (+phys/contig),
  storage 6 (+fat/name-protected); CI-сценарий desktop проверяет
  write/cat/cp/rm и отказ удаления защищённого файла. Харнесс: sendkey
  через raw()+дренаж пачками (cmd-вариант ждал ~2 с/символ — сценарий
  desktop не влезал в бюджет).
- Скриншоты fnd2d-*: +кадр OOBE save (перенос строки) и gui с перекрытием
  окон (about поверх cmd — контент терминала не лезет наверх).

**Критерий (выполнен):** host 55/55; QEMU 5/5 сценариев PASS; визуально
(скриншоты) — перенос текста в рамке, верхнее окно перекрывает терминал,
чистый терминал без INFO-спама; мерцание устранено двойной буферизацией
(единственная запись в VRAM — fb_present).

**Осталось на следующие этапы (осознанно отложено):** частичные
перерисовки (dirty-прямоугольники вместо полного кадра — GUI-1),
перемещение фокуса кликом только по рамке/заголовку, resize окон.

## [x] FND-2e. «Shell 2.0»: Start-меню, resize окон, настройки, notepad/calc (вставка перед FND-2)

**Зависимости:** FND-2c, FND-2d.
**Обоснование вставки:** запрос пользователя — десктоп «почти 1 к 1 как
в Windows 11»: полноценное Пуск-меню, растягивание окон, системные
настройки (от разрешения до времени), утилиты (notepad и др.).
**Состав:**
- Рендер: clip-прямоугольник в fb (fb_clip_set/screen) — контент окон
  не может выйти за рамки (системное закрытие класса «текст за рамкой»);
  частичный клип глифа 8x8 (без «рваного» нижнего ряда).
- Тема: runtime-акцент (uidraw_set_accent) и 4 процедурных обоев
  (Gradient/Bloom/Hills/Aurora); кэш обоев (fb_walllayer, отдельный
  слой + row-copy в кадр) — процедурный фон рисуется один раз.
- WM: resize окон за 8 зон (EDGE_PX, минимум 180x120), правый клик
  (контекстные меню рабочего стола/окна/иконки панели), двойной клик
  по иконкам рабочего стола, маршрутизация клавиатуры (dsk_kbd_event:
  Start → текстовые приложения → kshell).
- Панель задач Win11-стиля: центр, только иконки (процедурные иконки
  приложений), pill-индикаторы, закрепления (pins в fobos.cfg),
  часы+дата (12/24h), AMNESIA-бейдж.
- Start-меню: поиск по приложениям (подстрока без регистра), плитки,
  чип пользователя, питание (logout/reboot/poweroff/амнезия), логотип
  Fobos (планета с кольцом и спутником — чистая векторика).
- Приложения (gfx/dskapps.c): notepad (редактор с курсором/скроллом,
  New/Open/Save на FAT32), calc (целочисленный, цепочка слева направо,
  +−*/%, overflow/div0 → «E»), settings (System/Display/Time/
  Personalization), обновлённые explorer (скроллбар, fit-имена) и
  about/viewer (перенос/усечение текста).
- Настройки: fobos.cfg v2 (mode/res/wall/accent/time24/pins) через
  общий парсер common/cfglite (ядро + загрузчик); разрешение
  применяется загрузчиком (GOP query_mode/SetMode до захвата FB);
  время — rtc_write_time (CMOS, BCD/bin, контрольное чтение).
- console: con_resize — смена сетки без потери контента (растягивание
  окна терминала).
- kshell: +6 команд (notepad/calc/settings/start/apps/pins) — 38.
- Тесты: host 63/63 (+8 cfglite), kselftest 69/69 (+8 cfglite, +bcd);
  CI desktop-сценарий дополнен проверками GUI-команд с возвратом фокуса
  кликом по таскбару (HMP mouse_move/mouse_button в экранных
  координатах; sendkey-хелпер печатает ТОЛЬКО символы — «esc» в нём
  буквы, не клавиша).
- Исправлено по ходу: консоль терминала стиралась следующим кадром
  (заливка клиента + con_flush по dirty — теперь con_mark_dirty перед
  каждой отрисовкой кадра); Start не перерисовывался по команде `start`
  (toggle теперь запрашивает кадр).

**Критерий (выполнен):** host 63/63; QEMU 5/5 сценариев PASS (desktop
155.8 с: apps/pins/notepad/calc/settings/start + залоченный режим через
ребут); скриншоты fnd2e-gui (Start-меню + окна + панель с иконками),
fnd2e-desktop (TUI, 38 команд), fnd2e-login.

**Осталось на следующие этапы (осознанно отложено):** редактирование
имени файла в notepad (клик-позиция курсора есть, ввод имени — кнопкой),
maximize/минимизация окон, перетаскивание иконок рабочего стола,
dirty-прямоугольники (GUI-1), кириллица в GUI (Unicode-шрифт).

## [x] FND-2f. Стабилизация по баг-репорту: курсор, иконки, LFN-запись FAT32 (вставка перед FND-2)

**Зависимости:** FND-2e.
**Обоснование вставки:** баг-репорт пользователя по скриншотам —
(1) квадрат-артефакт на «спавне» курсора, (2) грубые иконки,
(3) символ питания в Start обрезан, (4) раздвоение консоли после
перезапуска окна терминала, (5) в explorer не видны файлы,
(6) файл из notepad не находится на том месте, куда его записала ОС.
**Состав:**
- Курсор — кадровый протокол (uidraw): GUI-режим рисует спрайт в скобках
  erase→draw внутри кадра композитора; TUI — события мыши меняют только
  координаты, зона старого спрайта перекрашивается ИЗ ЯЧЕЕК консоли
  (con_flush_rect_px) перед con_flush; erase без валидного штампа —
  честный no-op. Следы курсора невозможны по построению в обоих режимах.
- Консоль терминала привязана к окну НА КАЖДОМ кадре (cmd_console_sync
  внутри dsk_redraw, клип = клиентская область); dsk_init сбрасывает
  консольную сессию (ui_console_session_reset) — контент прошлой

## [x] FND-3a. Юзерспейс: процессы, планировщик, syscall ABI v0 (вставка перед FND-2)

**Зависимости:** FND-2f.
**Обоснование вставки:** запрос пользователя («полноценный юзерспейс,
системные вызовы и т.д.»). Полный FND-2 (buddy/VMM/ACPI/APIC/SMP) не
блокирует минимальный честный юзерспейс: bitmap-аллокатор и загрузочные
таблицы страниц покрывают потребности одного CPU, а архитектура
(syscall-диспетчер, реестры кадров, RR-планировщик) не меняется при
появлении buddy/SMP. Полный FND-3 (IPC, wait/waitpid, fork) — следом.
**Состав:**
- arch/tss: TSS-дескриптор (слоты 6-7, селектор 0x30), RSP0 (обновляется
  планировщиком), IST1 для #DF (отдельный 8 КиБ стек), EFER.NXE,
  CR4.SMEP/SMAP по CPUID (SMAP требует STAC/CLAC в copy_to/from_user).
- GDT: UCODE-дескриптор дублируется в слотах 0x18 и 0x28 — семантика
  SYSRET различается между AMD/QEMU (CS = STAR[63:48]+16) и Intel (CS =
  STAR[63:48]); с дублем оба варианта дают валидные сегменты (0x2B/0x1B).
- mm/vmm: адресное пространство на процесс (PML4 + копии разделяемых
  записей), W^X (NX на данных/стеке, RX на тексте), 4 КиБ-страницы.
  Ключевое решение — РЕЕСТР КАДРОВ на процесс (явный список таблиц и
  данных): обход дерева при destroy невозможен, т.к. user-маппинги
  соседствуют с identity-bigpages загрузчика (2 МиБ, PS на уровне PD) в
  тех же слотах PML4[0]; отличить общие таблицы по битам нельзя.
  vmm_map_page: table_ensure_private (клон общих PDPT/PD перед записью —
  иначе user-маппинги стали бы видимы ядру) + bigpage_split (расщепление
  identity 2 МиБ в 4 КиБ-таблицу). U-флаг обязателен на ВСЕХ уровнях
  user-ветки (U/S = AND по уровням).
- sys/task: пул задач (16, без динамической памяти), RR-планировщик с
  квантом 10 мс, вытеснение ТОЛЬКО user-кода по таймеру (ядро не
  вытесняется — синхронизация не нужна), блокировка на wait-очередях
  (клавиатура), zombie-reap (ресурсы освобождает следующая задача после
  switch), стек ядра 64 КиБ на задачу, kill по исключениям ring 3
  (#UD/#NP/#SS/#GP/#PF — завершение процесса вместо паники ядра).
- sys/syscall: syscall/sysret (EFER.SCE, LSTAR, STAR, FMASK очищает
  TF/IF/DF/NT/AC), таблица ABI v0 из 8 вызовов: exit, write(консоль),
  read(клавиатура, блокирующий), getpid, uptime, sleep, brk, abi_version.
  copy_to/from_user: проверка диапазона (vmm_user_range_ok: все страницы
  P|U, bigpages прототипа отвергаются) + STAC/CLAC при SMAP.
- sys/elf: ELF64-парсер ET_EXEC/EM_X86_64 (чистый, общий с host-тестами;
  PT_INTERP/ET_DYN — честный K_ENOSYS) + загрузчик с callback-маппингом.
- shell: команды `run NAME` (\fobos\NAME.ELF) и `ps` (таблица задач,
  статистика vmm/ctx-switches/syscalls). mem: исправлены единицы
  (печатал MiB под меткой KiB).
- user-space: user/lib (fos.h — syscall-обёртки, мини-printf без SIMD),
  программы hello (маркер USEROK), mtest (SYS_brk: рост/чтение-запись/
  возврат барьера — маркер MEMOK), kecho (эхо клавиатуры, ESC — выход).
  Сборка: -mgeneral-regs-only (состояние FPU не сохраняется — ограничение
  задокументировано), user.ld: text 0x400000 RX, data RW, heap 0x600000,
  стек 64 КиБ на 0x7fffe000.
- Хуки драйверов: timer_set_tick_hook (квант планировщика),
  kbd_set_wake_hook (пробуждение читателей SYS_read).
- Тесты: kselftest +5 (elf/valid-exec, validate-ok, bad-magic, bad-class,
  et-dyn, phoff-range, entry-kaddr, seg-kaddr, filesz-gt-memsz, seg-eof —
  синтетические образы, собранные байт-в-байт) + task/pool-init; host 84.
- CI: сценарий 6 userspace — Shift-консоль → run hello (spawn/USEROK/exit/
  reap) → run mtest (MEMOK) → ps (пул вернулся к idle) → mem до/после
  (нет утечки кадров) → негатив run nosuch (K_ENOENT без паники) →
  повторный запуск (реюз слота) → poweroff.

**Критерий (выполнен):** host 84/84; QEMU сценарий userspace PASS
(hello печатает USEROK через syscall write в ring 3, exit code=0,
реюз слота, mem до/после совпадает — утечек нет); изоляция: user-буфер
в kernel-диапазоне отвергается vmm_user_range_ok, фолт user-кода
завершает процесс, а не ядро.

**Осталось до закрытия FND-3 (осознанно отложено):** IPC (порты +
разделяемая память), wait/waitpid, fork/vfork, сохранение FPU-состояния
(XSAVE), таймерные wait-очереди, сисколл-трассировка, пер-процессные
дескрипторы консоли.

## [x] FND-3b. Системный установщик с выбором диска (вставка после FND-3a)

**Зависимости:** FND-2c (AHCI/FAT32 в ядре), FND-3a.
**Обоснование вставки:** запрос пользователя («выбрать куда установить
систему и многие функции установщика с больших ОС по типу Windows»).
Установщик работает в UEFI-фазе — до ядра: прошивка уже даёт BlockIo для
всех дисков машины, значит мастер может размечать/копировать даже там, где
у ядра ещё нет драйвера (NVMe, USB-носители).

**Состав:**
- boot/uefi/setup: мастер из 7 экранов в стиле классических установщиков
  настольных ОС: welcome → license (принятие лицензии REQUIRED) → disks
  (список всех BlockIo-устройств с моделью/размером/таблицей разделов) →
  drive options (advanced): удалить раздел / создать раздел с выбором
  размера / отформатировать FAT32 (быстрое форматирование) → confirm
  (сводка + явное предупреждение о потере данных) → working (прогресс
  копирования дистрибутива с процентами) → done (перезагрузка).
- Все разрушительные операции требуют подтверждения y/n; установка с
  дистрибутива запускается автоматически при «свежем» втором диске, диск
  загрузки исключается из целей (его ESP обслуживает текущий сеанс).
- Разметка цели: защитная MBR + раздел 1 (type 0xEF, ESP: \EFI\BOOT\
  BOOTX64.EFI, \fobos\kernel.elf, user-ELF, fobos.cfg) + раздел 2
  (type 0x0C, том данных \fobos пользователя); оба тома — FAT32 через
  общий common/fmtfat32 (тот же код, что в ядре и host-тестах).
- После установки: перезагрузка в установленную систему, OOBE, затем
  setup_target_write_cfg переносит конфигурацию пользователей на целевой
  ESP (\fobos\setup.cfg).
- Общий код разметки (common/mbr) и форматирования (common/fmtfat32,
  fmtcalc) — единый для загрузчика, ядра и host-тестов (без копипасты).

**Отладка (инструментальная):** зафиксирован регресс коммита с объединённым
FND-3a+3b: use-after-free в bootcfg_load (espfile_free вызывался ДО
cfglite_parse; отладочная OVMF заливает freed-страницы паттерном 0xAF →
загрузчик «не видел» mode=gui в fobos.cfg, записанном ядром, маркер
[loader] bootcfg: mode=gui пропадал, сценарий desktop фаза B падал).
Локализовано цепочкой: serial-логи сценариев → инструментирование
bootcfg_load (дамп size/kvs/hex) → хост-дамп образа (scripts/
diag_cfg_dump.py: на диске содержимое корректно) → вывод: мусор живёт
только в памяти загрузчика. Фикс: освобождение строго после последнего
использования буфера (kvs указывают внутрь него).

**Критерий готовности (выполнен):** `make verify` зелёный — host-тесты
(+fmtcalc/fmtfat32/mbr на разметку и формат), QEMU-сценарий install:
мастер проезжает end-to-end на втором чистом диске (384 МиБ), разметка
проверяется перезагрузкой в установленную систему.

## [x] FND-HW1. Подготовка к реальному железу (вставка после FND-3b)

**Зависимости:** FND-3b.
**Обоснование вставки:** запрос пользователя («подготовить по максимуму
к реальному голому железу, QEMU прощает ошибки, а железо нет — тесты
будут на реальном ПК»). Аудит на «QEMU-допущения» дал три блока.

**Состав:**
- loader: framebuffer выше 4 ГиБ. На реальных платах GOP-буфер часто
  лежит над 4 ГиБ (PCIe BAR), QEMU кладёт его ниже — прежний код отвечал
  отказом (`die "framebuffer above 4 GiB"`). Теперь диапазон фиксируется
  в g_prot.fb_* и отображается ленивыми PD (map_high_region, лимит
  512 ГиБ); для < 4 ГиБ — атрибуты UC (PWT|PCD) на больших страницах,
  для > 4 ГиБ — сразу в PDE. UC обязателен: WB-запись в MMIO на реальном
  железе даёт спекулятивные транзакции к устройству и медленный доступ.
- kernel/drivers/pci: рекурсивная энумерация шин через мосты PCI-to-PCI
  (класс 06/04, заголовок типа 1, secondary bus @0x19). Прежний проход
  видел только шину 0 — на реальных платах SATA/USB/LAN часто живут за
  мостами. Защита от циклов: bitmap посещённых шин (256 бит) + лимит
  глубины 8; PCI_MAX_DEVICES 32 → 64 (мосты тоже устройства).
- kernel/kmain: отсутствие контроллера 8042 больше не паника (на части
  ноутбуков PS/2 нет вообще): ps2_init → WARN, клавиатура/мышь
  пропускаются, kbd_poll при неинициализированном драйвере безопасно
  возвращает «пусто», загрузка продолжается.
- Уже было устойчиво к железу (проверено аудитом, без изменений):
  ExitBootServices с ретраем по спецификации; физаллокатор fail-closed
  (выдаёт только CONVENTIONAL-кадры, runtime/NVS/MMIO не трогает);
  AHCI с таймаутами 8 с, спин-апом, проверкой сигнатуры и K_ENODEV;
  PS/2-обмен только через bounded-ожидания; SMEP/SMAP/NXE по CPUID;
  UCODE-дубль для расхождений SYSRET AMD/Intel; отключение watchdog
  прошивки; проверка сигнатур EFI-таблиц на чужой прошивке.

**Критерий готовности (выполнен):** `make verify` зелёный (все 7
сценариев QEMU, включая install на втором диске); README дополнен
разделом «Тестирование на реальном железе» с требованиями, процедурой
записи носителя, отладкой по COM1 и списком известных ограничений.

## [ ] FND-2. Память и прерывания «по-взрослому»

**Зависимости:** FND-1, FND-2a (таймер и IRQ-диспетчер уже используются).
**Состав:**
- Buddy-аллокатор страниц (замена bitmap; bitmap остаётся как слой
  диагностики фрагментации) + slab-аллокатор ядра (кэши объектов, magic-числа,

- ACPI: RSDP через EFI Configuration Table → RSDT/XSDT → MADT/FADT.
- APIC (LAPIC + I/O APIC), таймер (TSC-калибровка через PM-timer), перенос
  журнала на реальные метки времени.
- SMP: загрузка AP (INIT-SIPI), per-CPU области, спинлоки с lockdep-проверками
  порядка захвата (debug-сборка).
**Критерий:** стресс-тест аллокатора и таймера в QEMU на 2+ CPU без паник
(2 часа), дамп всех дескрипторов ACPI в лог.

FAT32); DLL-лоадер. Обязательный артефакт этапа: `docs/win32-coverage.md`
(матрица: функция / статус / приоритет / чем проверена). До появления
работающих Notepad-класса GUI-приложений слово «поддержка Windows» не
используется.
**Критерий:** Win32-калькулятор и порт notepad.exe: окно, ввод, меню,
сохранение файла через FAT32.

## [ ] WIN-2. BIOS-путь загрузки (параллельный, можно стартовать после FND-4)

Собственный stage-1 (MBR→VBR), A20, protected mode→long mode, E820.
Обоснование откладывания: UEFI-путь закрывает целевое железо проекта и всю
разработку под QEMU; BIOS-ветка дублирует загрузочный контракт и должна
подхватить уже стабилизированный FBPI v1 (с динамическим размещением ядра).

## Постоянный бэклог (не этапы, снимаются по ходу)

- **KASLR ядра** — после того как VMM научится строить таблицы с нуля
  (FND-2); до этого фиксированная база — задокументированное ограничение.
- **Оптимизация string/memcpy (SSE + ERMS-путь)** — с FND-4, когда есть
  бенчмарк копирования FAT32-блоков; до этого общий код с
  `-fno-tree-loop-distribute-patterns` (защита от рекурсии memset→memset).
- **Watchdog ядра и NMI-стек** — вместе с SMP (FND-2).
- **Журналирование ФС** — осознанно НЕТ по ТЗ; вместо него FS-чекер (FND-4).
- **Сетевой стек** — вне обязательного объема ТЗ; не заявляем.
