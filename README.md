# Fobos OS

Графическая десктопная операционная система для x86_64 (UEFI + BIOS),
написанная с нуля: без Linux/XNU/NT/Redox, без загрузчиков сторонних
производителей. Ядро — монолитно-модульное (C11 freestanding), user-space —
планируется Rust/C++20 по месту обоснования.

**Текущий статус: этапы FND-3b и FND-HW1 закрыты** — **системный установщик
с выбором диска** (мастер из 7 экранов в UEFI-фазе: лицензия, список
дисков, drive options — удаление/создание/форматирование разделов,
подтверждение, прогресс копирования, перезагрузка в установленную
систему) и **подготовка к реальному железу** (framebuffer выше 4 ГиБ
через ленивые PD с атрибутами UC, рекурсивная PCI-энумерация через
мосты, отсутствие PS/2 не паника; см. README-раздел «Тестирование на
реальном железе»). Ранее: FND-3a — **юзерспейс и системные вызовы**:
процессы ring 3 (пул задач, вытесняющий RR-планировщик с квантом 10 мс,
ядро не вытесняется), **syscall ABI v0** (syscall/sysret, 8 вызовов: exit/
write/read/getpid/uptime/sleep/brk/abi_version, версионирование через
SYS_abi_version), **VMM** (адресное пространство на процесс, W^X с NX,
SMAP/SMEP, клоны разделяемых таблиц + расщепление identity 2 МиБ,
реестры кадров — destroy без обхода дерева), **TSS** (RSP0, IST1 для #DF,
EFER.NXE), **ELF64-загрузчик** (ET_EXEC, чистый парсер общий с host-тестами),
kill по фолтам ring 3 (завершение процесса вместо паники ядра), zombie-reap,
команды kshell **`run NAME`** и **`ps`**; user-space рантайм без libc
(user/lib) и программы hello/mtest/kecho. Ещё раньше: FND-2f (курсор/
иконки/LFN-запись), FND-2e (Start-меню/resize/настройки/notepad/calc),
FND-2d (двойная буферизация/z-order), FND-2c (PCI/AHCI/FAT32, GUI-десктоп,
`fos == gui|tui [--lock]`, амнезия), FND-2b (OOBE/вход/сессии/Shift-консоль),
FND-2a (интерактивность) и FND-1 (загрузка UEFI → long mode → higher-half).
Подробности: `docs/roadmap.md`.

## Сборка и проверка

Требования: `gcc >= 11` (или совместимый clang), `ld` с эмуляцией `i386pep`
(стандартный binutils x86_64), `nasm >= 2.15`, `python3`. Для прогона в
эмуляторе: `qemu-system-x86_64` + прошивка OVMF.

```sh
make            # BOOTX64.efi + kernel.elf (валидация раскладки обязательна)
make esp        # build/esp.img — FAT32+MBR: BOOTX64.EFI, \fobos\kernel.elf, NOTES.TXT
make host-tests # unit-тесты на host-инструментарии (84+ теста)
make selftest   # headless QEMU/OVMF: 7 e2e-сценариев (ESP пересобирается с нуля)
make verify     # всё выше разом
make run        # интерактивный прогон в окне QEMU (скриншоты: scripts/take_shots.py)
```

Пути к QEMU/OVMF переопределяются переменными `FOBOS_QEMU` и
`FOBOS_OVMF_DIR`; каталоги ROM добавляются автоматически.

Успешный verify выглядит так:

```
host-tests: PASS (0 failed)
qemu_selftest: === сценарий oobe ===     # OOBE -> логин -> десктоп -> logout -> reboot
qemu_selftest: === сценарий persist ===  # настройка пережила перезапуск (файл/переменная)
qemu_selftest: === сценарий esc ===      # ESC в boot manager -> новый OOBE
qemu_selftest: === сценарий shift ===    # SHIFT -> kernel console -> poweroff
qemu_selftest: === сценарий desktop ===  # storage/FAT32, ls/cat/write/cp/rm, амнезия, fos-режимы + --lock
qemu_selftest: === сценарий userspace === # FND-3a: run hello/mtest (syscalls), ps, mem до/после, негатив
qemu_selftest: === сценарий install ===  # FND-3b: мастер установки на втором диске end-to-end
qemu_selftest: PASS (всё зелёное)
```

`make selftest` пересобирает ESP с нуля (сценарии пишут setup.cfg/fobos.cfg
в общий образ); `make run` сохраняет содержимое диска между запусками.

## Запуск и управление (FND-2f)

Поток загрузки:

1. **Boot manager (1 с):** `ESC` — сброс Setup (OOBE заново),
   `SHIFT` — загрузка сразу в kernel console (режим обслуживания).
2. **Первый запуск:** графический OOBE-мастер — приветствие, имя машины
   (умолчание `fobos-pc`), имя пользователя, пароль (мин. 4, с подтверждением),
   «добавить ещё пользователя?», сохранение. Настройки пишутся в файл
   `\fobos\setup.cfg` на ESP (первичный носитель; UEFI-переменная FobosSetup
   — фолбэк) и переживают перезагрузку/выключение.
3. **Экран входа:** имя + пароль (единственный пользователь предзаполнен),
   кнопки Log in / Reboot / Shut down (мышь и F2/F3), часы RTC вверху.
   Неверный пароль — сообщение и повтор.
4. **Рабочий стол (TUI по умолчанию):** консоль kshell от имени пользователя,
   статус-бар с датой/временем RTC, памятью, uptime и мышью.
5. **GUI-десктоп «Shell 2.0» (`fos == gui`):**
   - **обои:** 4 процедурных варианта (Gradient / Bloom / Hills / Aurora),
     кэшируются в отдельном слое (fb_walllayer) — кадр начинается с
     быстрого row-copy, а не перерисовки фона;
   - **иконки рабочего стола:** колонка слева (cmd/explorer/notepad/calc/
     settings), одиночный клик — выделение, двойной — запуск;
   - **окна:** перетаскивание за заголовок, **растягивание за 8 зон**
     (4 края + 4 угла, минимум 180x120), фокус/z-order, кнопка закрытия;
     содержимое окон клиппится на уровне рендера (fb_clip_set) — контент
     физически не может выйти за рамку;
   - **панель задач:** центрированная группа «Пуск + только иконки»
     (без текста), pill-индикаторы запущенных, закрепление/открепление
     правым кликом (pins сохраняются в fobos.cfg), справа — индикатор
     AMNESIA и часы + дата (12/24h);
   - **Start-меню:** кнопка с логотипом Fobos (планета с кольцом и
     спутником), поиск по приложениям (строки/плитки, Enter/стрелки/Esc),
     чип пользователя, меню питания (Log out / Reboot / Power off /
     Amnesia on-off);
   - **правый клик:** на рабочем столе — меню (Refresh, Terminal, Display
     settings, Personalize, About); на окне — Close/Pin; на иконке панели —
     Pin/Unpin/Close;
   - **приложения:** cmd (kshell в окне; перезапуск окна не дублирует
     консоль — она привязана к окну на каждом кадре, история сохраняется),
     explorer (FAT32: навигация, скроллбар, Up/View/Del/Refresh; стартует
     в \fobos — пользовательском каталоге notepad), about, viewer
     (PgUp/PgDn), **notepad** (ввод/курсор/скролл, New/Open/Save на
     FAT32, защита системных имён; сохранение — \fobos\ИМЯ, имя без
     ведущего «\»; длинные имена пишутся как LFN с алиасом ~N; путь
     сохранения печатается в терминал, открытый explorer перечитывает
     каталог сразу), **calc** (целочисленный, цепочка
     слева направо, + - * / %, проверка переполнения/деления на 0),
     **settings** (System / Display / Time / Personalization);
   - **настройки (Settings):** Display — выбор разрешения (7 режимов,
     пишется res=WxH в fobos.cfg, применяется загрузчиком через GOP
     SetMode при следующей загрузке); Time — часы/дата с кнопками +/-
     и Apply to RTC (запись в CMOS), формат 12/24h; Personalization —
     обои и акцентный цвет (применяются немедленно, хранятся в
     fobos.cfg); System — сводка о системе.
6. **Kernel console (Shift):** приглашение `fobos(kconsole)>`, сессии нет
   (`whoami` → `maintenance`); OOBE не требуется.

Клавиатура: US-раскладка, Ctrl+C/Ctrl+L в консоли, **Ctrl+Alt+Del —
перезагрузка** в любом режиме. В GUI ввод маршрутизируется: Start-меню и
текстовые приложения (notepad/calc) перехватывают клавиши, остальное —
kshell. Команды kshell: `help`, `about`, `uptime`, `date`, `ticks`, `mem`,
`whoami`, `hostname [имя]`, `users`, `useradd N` (только admin), `passwd`,
`logout`, `kbd`, `mouse`, `fbtest`, `font`, `condump N`, `selftest`, `echo`,
**`fos == gui|tui [--lock]`** (режим рабочего стола; `--lock` пишет
`\fobos\fobos.cfg` — режим переживает перезагрузку; `fos status` — текущий),
**`amnezia [on|off|status]`** (оверлей RAM; при включении записи на диск
не доходят), **`storage`** (AHCI/диск/FAT32/амнезия/счётчики IO),
**`ls [путь]`**, **`cat ФАЙЛ`** (до 4 КиБ), **`write ФАЙЛ [текст]`**,
**`rm ФАЙЛ`**, **`cp ИСТОЧНИК ПРИЁМНИК`** (до 64 КиБ), **`sleep МС`**
(1..60000), **`notepad` / `calc` / `settings`** (открыть GUI-приложение),
**`start`** (показать/скрыть Start-меню), **`apps`** (список приложений),
**`pins`** (список закреплений), **`run ИМЯ`** (запуск user-программы
`\fobos\ИМЯ.ELF` в ring 3 — hello/mtest/kecho; вывод попадает в консоль
и serial), **`ps`** (таблица задач: pid/имя/состояние/ring/тики + статистика
VMM и планировщика), `clear`, `crash confirm`, `reboot`, `poweroff`.
Системные имена (KERNEL.ELF, SETUP.CFG, FOBOS.CFG, BOOTX64.EFI) защищены
от удаления/перезаписи единым списком `fat_name_protected()` (explorer,
notepad и shell используют один и тот же).

Запись файлов — сквозная (write-through): завершившийся успехом Save из
notepad / `write` / `cp` уже находится на блочном устройстве (AHCI DMA).
Файл сохраняется в гостевом QEMU-диске (образе ESP); на стороне хоста он
виден после завершения работы виртуальной машины — проверка
`python3 scripts/verify_fnd2f.py` делает это автоматически (сохраняет из
notepad, гасит QEMU и читает FAT32 образа со стороны хоста).

Конфигурация `\fobos\fobos.cfg` (FND-2e): текстовые key=value (парсер
`common/cfglite`, общий для ядра и загрузчика): `mode=gui|tui` (залоченный
режим), `res=WxH` (разрешение после перезагрузки), `wall=0..3`,
`accent=RRGGBB`, `time24=0|1`, `pins=cmd,explorer,...`. Пишется Settings
и командой `fos == ... --lock`.

Безопасность паролей: пароли не хранятся — соль (16 Б) + KDF-хеш
(4096 итераций SHA-256), сравнение в постоянном времени. Рантайм-изменения
(passwd/useradd) volatile: база пользователей живёт в блобе загрузчика;
с файловой персистентностью аккаунтов — FND-4.

Экранный шрифт — ASCII 8x8 (public domain font8x8, общий для ядра и
загрузчика); кириллица рисуется точками до Unicode-шрифта (GUI-этапы).
Регенерация: `python3 scripts/gen_font.py`. Скриншоты всех экранов:
`python3 scripts/take_shots.py`.

## Структура

```
include/fobos/   — общий контракт loader↔kernel (types, errors, boot_info)
common/          — код для загрузчика, ядра и host-тестов: sha256, foboscfg,
                   fbpi (checksum/validate/конвертер цвета), font8x8
boot/uefi/       — UEFI-загрузчик: свои EFI-определения, ELF64-лоадер,
                   boot manager (ESC/SHIFT), OOBE-мастер (lgfx/lin/oobe),
                   UEFI-переменная FobosSetup, serial-лог
user/           — user-space (ring 3): lib (fos.h: syscall-обёртки,
                   мини-printf, без libc/SIMD), hello/mtest/kecho,
                   user.ld (text 0x400000 RX / data RW)
kernel/
  arch/          — GDT (ring0/ring3 + TSS 0x30), IDT (48 векторов, #DF->IST1),
                   tss (RSP0/IST1, EFER.NXE, CR4.SMEP/SMAP), PIC 8259,
                   диспетчер IRQ
  mm/            — физический аллокатор (bitmap; buddy — FND-2),
                   vmm (адресные пространства, W^X, клоны таблиц +
                   расщепление bigpage, реестры кадров)
  drivers/       — 16550 UART, framebuffer GOP, PIT, 8042/PS2, kbd, mouse,
                   RTC (CMOS-часы), PCI (энумерация/класс/бары),
                   AHCI (HBA, порты, DMA, IDENTIFY, LBA48 RW)
  fs/            — blk (блочный слой + MBR + амнезия), ovl (RAM-оверлей),
                   fat32 (том/каталоги/файлы RW + кэш FAT), fatp (чистая
                   логика: BPB, 8.3, LFN, записи — общая с host-тестами)
  gfx/           — fbcon, ui (панель/статус-бар TUI), uidraw (примитивы+курсор),
                   desktop (TUI/GUI-режимы, окна/композитор с z-порядком и
                   коалесингом кадров, иконки, панель задач,
                   explorer/about/viewer), splash, login
  sys/           — users (RAM-база + KDF), session (сессия/hostname),
                   power (reboot/poweroff),
                   task (пул задач, RR-планировщик, wait-очереди, reap),
                   syscall (syscall/sysret ABI v0, copy_to/from_user),
                   elf (ELF64-парсер + загрузчик)
  shell          — ядерная оболочка kshell (сессии, файлы, fos/amnezia,
                   run/ps, 40 команд)
  lib/           — log (уровни + ring + sink), kvsnprintf, string, spinlock, io
  selftest/      — общий набор тестов (ядро + host) + storage-тесты (FAT32 e2e)
scripts/         — pe_patch, check_kernel_elf, mkimg, qemu_selftest (сценарии),
                   screenshot, take_shots, gen_font
  tests/host/    — host-раннер unit-тестов (мок-карта памяти)
docs/            — boot-protocol.md (FBPI v0.1 + FobosSetup), roadmap.md
```

## Инженерные стандарты (кратко)

- Каждый публичный API возвращает `err_t`; игнорирование кода запрещено.
- Ноль предупреждений: `-Wall -Wextra -Werror` на всех слоях.
- Никаких `printf` в ядре — только `klog` (уровни, подсистемы, кольцевой буфер).
- Слои не знают о верхних: HAL → kernel services → драйверы → подсистемы.
- Критические модули покрыты тестами, исполняемыми и в QEMU, и на host.
- Кадровый конвейер графики: примитивы пишут ТОЛЬКО в активную поверхность
  fb (задний буфер или VRAM), кадр на экран выносит fb_present(); прямые
  записи в VRAM запрещены (теряют dirty-флаг — источник мерцания).
- Известные ловушки, уже найденные и закрытые (см. git-историю проекта):
  `-ftree-loop-distribute-patterns` превращает наши memset/memcpy в рекурсию
  (отключено флагом), `lgdt/lidt` требуют base сразу за limit (packed),
  флаги GDT-дескриптора идут в старшем ниббле байта 6, UEFI-протоколы не
  содержат EFI_TABLE_HEADER, OVMF грузит EFI-приложение в 0x100000 (поэтому
  ядро — по адресу 2 МиБ), после self-test 8042 устройства молчат без 0xF4
  (включение сканирования), dual-channel 8042 детектируется только пробой
  «очистить бит клока порта 2 и прочитать назад», GetVariable-запрос размера
  возвращает EFI_BUFFER_TOO_SMALL (это УСПЕХ чтения, а не ошибка),
  Shift-одиночку OVMF не отдаёт через ConIn — только прямой опрос 8042,
  kselftest обязан восстанавливать глобальное состояние (снапшоты
  users/session), иначе повторный selftest в живой сессии её разрушает,
  H2D FIS: раскладка как в Linux ata_tf_to_fis — device в байте 7, а не 4
  (перепутанные байты дают «чтение сектора 63» вместо 0 — QEMU честно
  исполняет CHS-запрос), кластерный LBA в FAT32 считается от data_lba
  (reserved + все FAT), а не от reserved (иначе каталоги читаются из зоны
  FAT), ovl-тесты selftest обязаны восстанавливать продакшн-бэкенд оверлея
  (иначе блочный IO ядра уходит в мок), recipe-строки Makefile — только
  табы (Edit-нормализация в пробелы ломает сборку), контент консоли
  терминала рисуется на z-позиции окна cmd (отдельный con_flush после
  композитора лез поверх верхних окон), K_ERANGE от fat_file_read = файл
  больше буфера (в cp это честный отказ, а не ошибка IO), sendkey через
  HMP-монитор — ~2 с на символ (cmd-вариант); для печати команд нужен
  raw()+дренаж пачками, иначе CI-сценарий не влезает в бюджет.

## Тестирование на реальном железе (FND-HW1)

QEMU прощает то, что железо не прощает, поэтому перед прогоном на ПК
проверьте требования и держите под рукой serial-лог.

**Требования к машине:**
- UEFI x64 (CSM/Legacy выключен; BIOS-путь загрузки — этап WIN-2, ещё
  не реализован). Прошивка обязана отдавать GOP (любой UEFI 2.x это умеет).
- SATA-контроллер в режиме AHCI (в UEFI Setup: SATA Mode = AHCI, не
  IDE/RAID). Диск, куда ставится система, должен быть виден как SATA:
  у ядра есть только AHCI-драйвер (NVMe — в backlog FND-2).
- Клавиатура PS/2 или переходник USB→PS/2. Драйвера xHCI у ядра нет
  (FND-2), поэтому после ExitBootServices USB-клавиатуры работать не
  будут независимо от «USB Legacy Support» в BIOS.

**Запись установочного носителя:**
```sh
make all esp                     # build/esp.img: MBR + FAT32 с загрузчиком
sudo dd if=build/esp.img of=/dev/sdX bs=4M conv=fsync status=progress
```
(/dev/sdX — флешка целиком; на Windows — Rufus в режиме DD.) Загрузчик
читается прошивкой через её FAT-драйвер, поэтому dd-образа достаточно.

**Установка:** загрузитесь с флешки. Если в машине есть второй чистый
диск — мастер установки запустится автоматически; иначе в окне boot
manager нажмите **I** («install»). Дальше: лицензия → выбор диска →
drive options (удалить/создать/форматировать разделы) → подтверждение →
копирование → перезагрузка → OOBE. Диск с флешкой-дистрибутивом
исключается из целей (его ESP обслуживает текущий сеанс).

**Отладка без экрана:** ядро и загрузчик пишут полный журнал в COM1
(115200 8N1). Пригодится USB-UART адаптер или второй ПК: экран паники
дублируется в serial со всеми регистрами и декодированием #PF. Без
UART смотрите на экран: паника рисуется там же.

**Известные ограничения (осознанные, roadmap):**
- используется только память ниже 4 ГиБ (identity-окно; buddy/SMP — FND-2);
- NVMe-диски и USB HID не драйвятся (FND-2), установщик при этом размечает
  любые диски через BlockIo прошивки;
- прерывания — legacy PIC + PIT; на платах без полного legacy-стека
  возможны пропуски тиков (APIC/HPET — FND-2);
- GPT-разметка при установке — после FND-4 (ядро читает только MBR,
  установщик пишет защитную MBR + 0xEF/0x0C).
